What the design got right (so a revision does not break it).

- **Q1: Yes, dropping upstream-loss invalidation is sound for equivalence to an attached window.** The gap’s `[redacted]` goes through `record_private_output`, history insertion and sequence advancement (`M:527`, `M:1968`, `M:1973`). Subsequent conservative redaction can publish another placeholder (`M:504`). Feed all those published bytes without resetting or discarding an existing terminal-parser prefix. This preserves equivalence to the damaged published stream; it does not recover lost PTY output.
- **The checkpoint fence correctly excludes unpublished redactor input.** Withheld prefixes remain pending (`M:554`), while ordinary publication inserts redacted bytes before advancing (`M:3395`). Feeding both publication paths before advancement and including the held escape tail exactly once can cover every published byte through S.
- **Q2: The basic two-order fence separation is correct.** If events 11–13 arrive first, existing renderers apply them and hydration can replace their journal entries with checkpoint 13. If the response arrives first, the new renderer can skip covered output/geometry while existing renderers still receive them. However, findings **1 and 5–8** prevent the complete protocol from guaranteeing correct hydration.
- **Q3: The three named locks alone have no reverse dependency established here.** Releasing the brief session guard before waiting for publication is correct. The registration check adds the registry lock and creates finding **2**; the written algorithm therefore cannot yet be called deadlock-free.
- **Per-attachment format selection and optional negotiation are appropriate.** The old Rust attach payload permits unknown fields (`apps/server/src/production/server_terminal.rs:1677`), and capability decoding already defaults absent booleans to false (`packages/contracts/src/environment.ts:74`). Preserve raw defaults in both directions.
- **Round-1 finding 10’s accounting omission is addressed:** D6 now names initial, resync, catch-up and raw restart snapshots. Current accounting only counts event output and resync history (`apps/server/src/production/server_terminal.rs:1158`); the revised rule reaches every variant. Finding **11** concerns the remaining copy-count claim.
- **Profiler and privacy direction is sound.** D12 specifies content-free fields, enabled checks and wrapper timing. This work adds no child process or service requiring a new exit watch or teardown step. Fixture sanitation now explicitly covers paths, titles and link targets.

Explicit round-1 verification: **#1 partially resolved** by separate fences; **#2’s second RIS resolved**, with new continuation failure **4**; **#3 partially resolved**, with missed-restart path **3** and lock issue **2**; **#8’s upstream/RIS premise corrected**, with preserved-state problems **7 and 9**; **#9 substantially improved**, with exhaustion/copy bounds **9–11**; **#10’s variant accounting resolved**, subject to **11**.

Open questions the design cannot answer.

- **D5’s required-state list is not complete.** Add explicit preservation or lifetime-correct fallback for:
  - **DECSCA protection on cells and pens:** prefix `ESC[1"qA ESC[0"q`, checkpoint, then `CR ESC[?2K`. A must survive selective erase. Installed xterm reproduced its loss when only visible text was restored (`X/common/InputHandler.ts:1130`, `:1147`). Returning the current pen to default does not remove protection from existing cells.
  - **Reverse wraparound, `?45`:** at four columns, prefix `ABCDE ESC[?45h ESC[2;1H`, checkpoint, then `BS X`. Installed xterm produced rows `ABCX` / `E`; default reverse-wrap state produced `ABCD` / `X` (`X/common/InputHandler.ts:765`). D3’s generic fallback can cover this, but it needs a named fixture. These are state requirements, not a proposed restoration order.
- **Vendoring is feasible, but fidelity remains unverified.** Cached avt 0.20.0 confirms `Terminal` and construction-time scrollback (`src/lib.rs:89`, `:106`), public wrap flags (`src/line.rs:568`), private saved state and two charset slots (`src/engine.rs:37`, `:102`), and a fixed-character cell (`src/cell.rs:4`). Revision 2 correctly withdraws the three-patch claim. The existing provenance/patch pattern fits (`Cargo.toml:148`; `third_party/portable-pty/UPSTREAM.md:12`).
- **Width parity:** D2 now covers contextual joining, wide-cell tails and margin behavior. VS16/ZWJ must retain the provider’s non-grapheme behavior, and ambiguous characters must use its default-width policy. No additional mismatch class is established beyond those gates, but the actual patched implementation remains untested. See the [pinned Unicode11 provider](https://raw.githubusercontent.com/xtermjs/xterm.js/6.0.0/addons/addon-unicode11/src/UnicodeV11.ts).
- **Palette verification needs browser-equivalent handling.** Headless xterm does not install the browser’s color-event handler; the browser does (`X/browser/CoreBrowserTerminal.ts:168`, `:189`). Explain how the harness compares palette state and color-query replies rather than treating ignored color operations as success. See [headless constructor](https://raw.githubusercontent.com/xtermjs/xterm.js/6.0.0/src/headless/Terminal.ts).
- Specify UTF-8 byte-range conversion for `startupQueries`. Rust byte offsets cannot be passed directly to JavaScript string slicing; include non-ASCII text before the range.
- Lock-time, retained-memory and upstream-lag results remain unknown. Synchronous parsing delays the publisher draining the bounded PTY channel (`M:3389`; `apps/server/src/terminal/pty.rs:598`). D9’s measurements are necessary evidence, not yet evidence of acceptable behavior.
