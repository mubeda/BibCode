## What the plan got right

- Keep the same history owners as the toolbar and leave Save on its existing hook. The toolbar already subscribes to the active rich editor and reads source history from the session. `FilePreviewPanel.tsx:898–914,1068–1075,1122–1126`, `fileEditingSession.ts:417–427`.
- Reuse the existing typed remote-delete operation and local confirmation pattern. The server already has a test proving deletion of the remote branch leaves its local namesake intact. `packages/contracts/src/gitManager.ts:205–214,252–258`, `GitManagerBranchDialogs.tsx:397–452`, `operations.rs:6085–6148`.
- Preserve the generic provider probe and terminal launch path. Inventory already invokes `--version`, and the existing panel handler forwards the structured terminal command. Codex and Claude remain the separate terminal-review allowlist. `provider_inventory.rs:731–747`, `ChatView.tsx:5004–5011`, `providerTerminalActions.ts:228–236`.
- The task IDs, titles and phase numbers match `progress.md:10–20`, and the spec checksum matches `plan.md:4` and `progress.md:4`. The three feature lanes can remain parallel after their ownership changes. The integration phase correctly depends on all three.

## Open questions the plan cannot answer

- Which native path does the packaged app actually take for Undo **and** Redo in each editor on macOS, Windows and Linux? The pinned source explains the different dispatch mechanisms. Runtime equivalence remains unverified.
- What is the intended user-visible behavior when a remote has no locally known default, or its tracking ref maps ambiguously to configured remotes? The design needs to settle this before exposing a destructive action.
- Which execution host can provide the required advisor review, and which `agy` versions will the launch tests qualify? Official documentation confirms the flags. No installed `agy` or native terminal launch was exercised.

This was a read-only review. `gh issue view` could not reach GitHub, so the approved spec governed the review. I checked the spec checksum, repository status, branch refs and Cargo argument parsing. I did not run builds, test suites, or native UI checks. CodeGraph sync was skipped because it can write generated data.

## Handling

Every finding was checked against the code before it was accepted.

1. Remote default and remote identity (Blocker): fixed. Verified at `apps/server/src/git/manager/refs.rs:315-346` (`is_default` is local-only, `*/HEAD` dropped). Phase 2 now owns the ref reader, the server marks each remote's default from `<remote>/HEAD`, and ambiguous or unknown cases have a decided behavior (Tasks 2.2, 2.3).
2. Sign-in path (Blocker): fixed. Verified at `GitManagerPanel.tsx:498-523`: the panel owns the sign-in flow, the toolbar runner does not. Task 2.3 reuses that flow in the toolbar path and tests declined, resumed and rejected cases.
3. Cargo filters (Blocker): fixed. One filter per `cargo test` invocation, the refusal test included, fixture order stated (Tasks 3.2, 3.3).
4. Edit menu branches (Major): fixed. Phase 1 starts with a diagnosis task with an ordered, exclusive decision rule per platform; branch B reuses `DesktopBridge.onMenuAction` (`packages/contracts/src/ipc.ts:1394`).
5. Packaged run skips the new spec (Major): fixed. Verified at `apps/desktop/e2e/wdio.conf.ts:50-78`. Phase 1 owns the allowlist; commands use `BIBCODE_E2E_SPEC` and `BIBCODE_E2E_PROFILER=1`.
6. Hook too broad, editors already bind the chords (Major): fixed, and it changes the premise. Verified in `@pierre/diffs/dist/editor/command.js`: `cmdOrCtrl+z`, `cmdOrCtrl+shift+z` and `ctrl+y` (Windows, Linux) are bound. Issue #398's guess that nothing binds them is disproved, so no web hook is planned up front; the failure is located first (Task 1.1).
7. Rename test green before the fix, checkout predicate (Major): fixed. Mixed guard arrays and the checkout cases are in Task 2.1.
8. Missing registration sites (Major): fixed. Tasks 3.2 and 3.3 name `production/control.rs`, the hermetic fixture lists, the display-name path and the Settings card files.
9. Model and effort from normalized defaults (Major): fixed. Task 3.4 reads the raw settings value.
10. Other chat-routing paths (Major): fixed. Task 3.4 applies one chat-eligibility rule at the fallback owners; Task 3.3 puts the server refusal before canonicalization.
11. Ownership and shared builds (Major): fixed. `docs/user/workspace-ui.md` moved to phase 4, `docs/architecture/providers.md` to phase 3, build lock rule stated in `plan.md`.
12. Publication order (Major): fixed. Phase 4 reviews and fixes first, then gates the final commit and logs its SHA; base is `origin/main`.
13. Task size, handoffs, skills (Minor): fixed where factual (tasks split, design note checked by path, `mstack-decisions` removed). Rejected in part: `rust-best-practices` and the advisor exist in the Claude Code session that executes the plan; the reviewer's own session lacked them.

Open questions: the native path per platform is Task 1.1's output; unknown or ambiguous remote metadata is decided in Task 2.2; `agy` is not installed anywhere, so launch is proven by command construction only (plan Risks).
