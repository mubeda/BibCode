# Plan review 3 (Codex gpt-6.2-sol, high, read-only), 2026-11-20

Scope: the phase 3 revision for the Antigravity chat over ACP.

Reviewed `a6ab7deb4` and the binding design at `f83380a44` against the current Rust and web callers. R11–R14 all have task IDs in the traceability table. The gaps are in what those tasks require their tests to prove.

## Findings

1. **P1 · R13 approval-required can start in an unsafe mode.** R13 requires the exact advertised `default` mode and refusal when it is absent. D-A5 permits startup without an advertised mode and points to a Cursor helper that can fall back to the current mode or the first non-plan mode, including `auto`. The measured peer exposes `mode` in `configOptions`. Revise D-A5 and Task 3.6 to use that option, require acknowledgement of `default` before sending a prompt, and test missing and rejected `default`, a switch from full access, stale approval responses after cancel, and `allow_once` when both allow choices exist. Define the precedence between approval-required and plan mode explicitly. [Spec R13], [ACP mode helper], [ACP config options]

2. **P1 · R13 restart safety has no test through the durable outbox.** Task 3.6 tests reopening a session in memory, and 3.7 tests delivery outcomes in one process. The production recovery path already moves a `sending` row for a provider without lookup to `uncertain`. D-A9 also overstates when `FrozenConversationLost` is returned. Ordinary durable delivery passes `abort_on_lost_resume = false` and can release a frozen session binding. Give 3.7 ownership of `apps/server/tests/turn_delivery_recovery.rs`. Extend the crash fixture to prove that an already-written prompt stays at one send after restart, the row becomes `uncertain`, and a subsequent new turn reopens the saved session. Pin the expected behavior separately for an unsent frozen turn whose conversation is gone. Include zero-byte, partial-write and lost-ack cases in the receipt test. [Task 3.7], [Recovery mapping], [Durable launch], [Crash fixture]

3. **P1 · Tasks 3.6, 3.8 and 3.9 lack a model and effort contract that round-trips.** D-A6 says to preserve wire IDs, but the shared effort controls and terminal extraction recognize `reasoningEffort`, `effort` and `reasoning`. The Cursor parser detects a `thought_level` _category_ and publishes `reasoning`. Spell out the BiBCode option ID and its mapping back to ACP `configId: "thought_level"`. Pin which model IDs win when both measured shapes are present, preserve the suffixed IDs for ACP, and test picker → saved default → exact ACP write. Test `--model` and `--effort` separately against the terminal mapping. The handshake does not establish that a suffixed ACP model ID is a valid TUI slug. D-A6 and the guide should state that limit. [Task 3.6], [Task 3.8], [Shared effort IDs], [Cursor parser]

4. **P1 · The chat tests can pass without a working first turn or the required error behavior.** Task 3.6 has an empty completion fixture, 3.7 checks launch and delivery results, and 3.9 stops at the terminal-open request. Add a scripted production-path turn that projects assistant text, tool activity and an approval, then carries a user response back to ACP. For the failure path, D-A8 maps sign-in failure to a generic `Provider` error, which the durable launch path treats as retryable. Require the exact sign-in and incompatibility messages to appear in the thread, a single actionable refusal, zero prompt writes, and a still-available terminal. Resolve D-A4’s unparsable `--version` case against R13’s minimum using the measured `agentInfo.version` as a fallback check. [Task 3.7], [Task 3.9], [Launch failure mapping]

5. **P1 · Profiler and child cleanup are only partly owned.** Task 3.7 references a supervision test that step 1 never defines. The shared exit reporter starts after `driver.start()`, so a child dying during `initialize` does not reach that reporter. Task 3.8 promises attribution, but the current control attachment passes the registry only to tool updates. Background refresh can also drop the probe future before a trailing cleanup call runs. Assign 3.7 the chat and launch-time version children, and 3.8 the inventory child and registry plumbing. Require bounded startup, cancellation-safe cleanup, and fixtures that distinguish unexpected exit from requested stop and prove attribution. Update Phase 4’s Profiler report, which still describes a terminal-only launch and chat refusal. [Task 3.7], [Startup], [Exit reporter], [Registry attachment], [Refresh cancellation], [Phase 4 report]

6. **P1 · The hygiene tests miss two production output paths.** D-A11 excludes option values and provider stderr from logs. The shared option reconciliation logger records the model and accepted option values, and the generic inventory version path can publish the first stderr line as `version`. A 3.6 in-memory log check and a 3.8 `_meta` omission check can both pass while those paths expose data. Assign 3.7 the production diagnostic assertion and 3.8 the sanitized version and snapshot assertion. Use synthetic markers in stderr, errors, version output, `_meta` and option values. Keep fixtures to the fields needed for the protocol behavior. [Phase fixture rule], [Option logging], [Version extraction]

7. **P2 · R11 and R12 have partial red-first coverage.** The Settings test can pass without adding a custom instance, and the terminal test can pass without asserting the request’s checkout, selected instance ID, binary override or observer status. Name those assertions explicitly in 3.9. In 3.2, make the raw-roster disabled test explicit and add Antigravity to the host-PATH fallback assertion. Assign the desktop hermetic assertion to 4.1, where it can run after Phase 1. For 3.8, add an explicit `control.rs` red test for quick-refresh retention and replacement after sign-in. Testing only the inventory probe cannot exercise the merge. [Tasks 3.2 and 3.9], [Host-PATH assertion], [Desktop assertion]

8. **P2 · The web file list misses the actual text-generation fallback and needs caller-level coverage.** Task 3.9 tests a disabled entry that the resolver already filters. D-A6 calls for an **enabled, ready, empty-catalog** Antigravity entry ahead of a usable provider. Assign `modelSelection.ts` and its test and include that test in the command. The commit-message RPC currently summarizes Git context directly, so the design’s assumption that it routes through chat should be removed. The model picker and code-review list consume generic instance actions, and quota usage is scoped to Claude and Codex. Those paths need no Antigravity registration. Give 3.9 assertions for the advertised model and effort in the picker, the composer’s plan-mode control, and the chat reviewer with its existing guard copy. `session-logic.ts` and the icon map are already assigned. [Task 3.9 file list], [Fallback], [Commit-message RPC], [Composer mode control], [Review choices], [Usage contract]

9. **P2 · The 3.6/3.8 file split is disjoint as written, but the handoffs and round-one ownership need fixing.** Define the shared handshake and model-option contract before both tasks start. If 3.8 imports code produced by 3.6, add the dependency or put the shared code in a prerequisite. Task 3.10 also claims `docs/architecture/overview.md`, which Phase 1.2 branch B owns in the same round. Put the overview update in 4.1 or serialize it. Update Task 3.1’s terminal-only instructions and Task 3.2’s references to retired tasks, and make the reviewed design commit an explicit input to 3.6 and 3.8. The spec’s Non-goals and the master plan still contradict D9. [Phase 3 handoffs], [Phase 1.2 ownership], [Master plan], [Spec Non-goals]

10. **P2 · R14 has an unowned changelog update.** The guard is assigned to 3.2, the guide and index to 3.10, and workspace UI and runbooks to 4.1. Task 3.10 says 4.1 consumes the guide for `CHANGELOG.md`, but neither task lists a changelog edit. Assign it explicitly and make the documentation checklist cover the full R14 list. Update the binding design’s evidence table with the four observed auth IDs, both model shapes, and measured option IDs and modes. Keep prompt, permission, resume and TUI flag-value behavior marked unverified by the handshake. [Spec R14], [Task 3.10], [Task 4.1]

11. **P2 · Three tasks are too broad for one agent session at the required proof level.** Split 3.6 into session setup/configuration and prompt/permission/cancel lifecycle. Split 3.7 into driver dispatch and durable restart/process coverage. Split 3.9 into Settings/terminal and chat picker/composer/reviewer acceptance. Task 3.8 is bounded once the parser contract and process ownership are fixed. Task 3.10 fits one session once the documentation ownership is resolved. [Task 3.6], [Task 3.7], [Task 3.9]
