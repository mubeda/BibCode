## Contradictions to read before starting

- R14 reverses two assertions in `volumes.rs`. The test `the_running_app_image_mount_is_hidden_before_it_is_read` asserts that `/tmp/.mount_OtherY` with `fuse.Other.AppImage` stays shown (`hidden.len() == 1`, `kept.len() == 3`) and that a `.mount_` mount is not hidden when no executable is known ("without the executable nothing matches"). - R45 names the "pairing rejection" log at `debug` in `auth/http.rs`. The only such log is `invalid_pairing_offer_response`, which logs `invalid pairing offer: {detail}` at `debug` while the client receives only `reason: "invalid_pairing_offer"`. ### Task 7.4: Log a rejected pairing offer and a rejected pairing credential at `warn` with a fixed class

- Satisfies: R45. Scenarios pinned: Given a pairing offer request that the server rejects, Then one `warn` line carries the trace id and the reason text. - Depends on: none
- Files: modify `apps/server/src/auth/http.rs` (`invalid_pairing_offer_response`); modify `apps/server/src/auth/service.rs` (`consume_grant`); test `apps/server/src/auth/http.rs` (the existing `tests` module); test `apps/server/src/auth/service.rs` (the `tests` module, next to the persisted-store tests that use `AuthService::new_with_persistence`)
- Interfaces: consumes (a) `fn invalid_pairing_offer_response(detail: &str) -> Response` in `http.rs`, whose callers pass a fixed literal or `PairingOfferInputError::to_string()` (fixed `thiserror` messages that hold no input text); (b) `async fn consume_grant(&self, credential: &str, proof_key_thumbprint: Option<&str>) -> Result<Grant, AuthError>` in `service.rs`, with its three rejection sites; (c) the existing `Repositories::get_auth_pairing_link_by_credential(&self, credential: String) -> Result<Option<AuthPairingLink>>`, which selects the row with its `expires_at`, `consumed_at`, `revoked_at` and `proof_key_thumbprint` columns. Produces: `invalid_pairing_offer_response` logging at `warn` with the same target, `trace_id` field and message; and a private `fn pairing_rejection_class(...) -> &'static str` in `service.rs` returning one of these fixed tokens, with this precedence when several apply: `empty` (the trimmed credential is empty), `unknown` (no row, or no in-memory pairing holds it), `revoked` (persisted rows only), `already_used`, `expired`, `proof_key_mismatch` (the link requires a proof key and the presented thumbprint differs or is absent), `desktop_bootstrap_expired` (the desktop bootstrap credential matched but its time ran out), `unclassified` (the extra read failed). Each refusal logs `tracing::warn!(target: "bibcode_server::auth", class, "a pairing credential was refused")`, once, before `Err(AuthError::InvalidCredential)` is returned. The HTTP response is unchanged for both paths.
- What the code can tell apart today, with no schema change, per storage mode. Persisted mode (`self.repositories` is `Some`): `consume_auth_pairing_link` runs one `UPDATE ... WHERE credential = ? AND revoked_at IS NULL AND consumed_at IS NULL AND expires_at > ? AND (proof_key_thumbprint IS NULL OR proof_key_thumbprint = ?) RETURNING ...` and returns `None` for every cause; the row itself stays after a revoke, a use or an expiry. So `consume_grant` makes one extra read on the refusal path only, `get_auth_pairing_link_by_credential`, which selects existing columns (no migration), and can report `unknown`, `empty`, `revoked`, `already_used`, `expired` and `proof_key_mismatch`. A row consumed by a racing request between the two statements is reported as `already_used`, which is true. In-memory mode (`self.repositories` is `None`, as the plain `AuthService::new` builds it): `revoke_pairing` removes the record (`state.pairings.remove`), and `issue_pairing_for_subject` and `list_pairings` prune consumed, revoked and expired records, so a later lookup finds nothing. In-memory can therefore report `unknown` and `empty`, `already_used` and `expired` only while the record has not been pruned, `proof_key_mismatch`, and `desktop_bootstrap_expired` (the desktop bootstrap check comes first in `consume_grant`); a revoked in-memory pairing reports `unknown`. This satisfies R45, and no record is retained only to name the reason in a log. The credential column holds the credential text, so the lookup uses the presented text, and the text is never logged.
