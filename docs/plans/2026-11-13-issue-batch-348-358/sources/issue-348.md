Both split and single viewport callers pass `visible` (`apps/web/src/components/ThreadTerminalPanel.tsx:2916`, `:2947`). The center wrapper also accepts terminals without a command, so this is not a separate AI-only renderer.
- (measured) `TerminalViewport` constructs xterm with FitAddon, opens it, and calls `fitTerminalSafely`; the helper catches fit exceptions and returns a boolean that these sizing callers do not check (`apps/web/src/components/ThreadTerminalPanel.tsx:561`, `:1257`, `:1318`, `:1421`). The manifest declares xterm `^6.0.0`, fit `^0.11.0`, and optional WebGL `^0.19.0` (`apps/web/package.json:36`). No separate canvas addon is declared there. (inferred) With WebGL off/failed, the path uses xterm's default non-WebGL renderer; this trace does not establish the exact underlying renderer implementation from dependency source.
- (measured) Right-panel dragging updates width once per animation frame and commits the pending final width on pointer-up (`apps/web/src/hooks/useResizableWidth.ts:150`, `:182`). `PreviewPanelShell` applies that width to the inline panel (`apps/web/src/components/preview/PreviewPanelShell.tsx:30`, `:48`); the adjacent center column is flex-sized (`apps/web/src/components/ChatView.tsx:7327`). Its callback cancels earlier pending frame/timer work, runs `size("layout")` in a frame, then clears the texture atlas and calls `refresh(0, rows - 1)` after 50 ms (`:2318–2349`). (inferred) A right-panel width change can therefore produce the extra measurement/size reconciliation **and full repaint** that clears the reported fault; source inspection alone cannot identify which operation actually repairs it.

The manager publishes after enqueueing; the worker applies the native resize asynchronously and warns if it fails. (inferred) An RPC success/size echo alone does not prove the native PTY accepted the new dimensions.

### Ranked hypotheses

1. **(inferred) Lifecycle recovery does not consistently include the repaint/font-completion work present on container resize.** AI commands wait for authoritative host configuration before creating a renderer (`apps/web/src/components/ThreadTerminalPanel.tsx:992–995`, `:1246–1248`). The font effect can run while no terminal exists and return; it depends only on `shouldRender` and `terminalFontFamily`, not renderer epoch/config readiness (`:2064–2091`). The observer effect also depends only on `shouldRender`, and an early notification returns if no terminal exists (`:2328–2330`, `:2367`). The epoch effect later requests sizing but no explicit refresh (`:2369–2386`); the 30 ms mount timer also only requests sizing (`:1964–1969`). **(guess)** If initial observer delivery precedes delayed creation, font metrics or paint could remain stale until a real box change supplies the missing trailing repaint. Existing initial fit, replay writes, and xterm's own repaint behavior may already recover many cases; this is a testable gap, not proof of the report's cause.
2. **(inferred) Logical visibility can differ from measurable geometry.** Center hosts accept zero dimensions (`apps/web/src/components/CenterPanelSurfaceHosts.tsx:94–111`); visibility requires an active surface and an existing rect, not a positive rect (`:292–304`). `ChatView` passes center focus eligibility but not `context.visible` to `CenterTerminalPanel` (`apps/web/src/components/ChatView.tsx:1001–1013`); right-panel maximize makes the center column width zero (`:7327–7332`). Dimension proposal clamps finite values and returns null for unavailable/error cases without scheduling a retry (`apps/web/src/components/terminalSizing.ts:11–24`). **(guess)** A transient hidden/zero box or deferred layout can therefore leave a renderer waiting for another layout event or measured size; test zero→positive recovery and restoration to the same old dimensions. This is not evidence that ResizeObserver necessarily misses such transitions.
3. **(inferred) Font/DPR invalidation has narrower application coverage than general layout.** The font helper explicitly loads the bundled font once through `document.fonts.load`, including a caught failure, while the viewport only reruns its font effect on visibility/font-family changes (`apps/web/src/lib/terminalFont.ts:52–64`; viewport `:2064–2091`). There is no general `document.fonts.ready`/`loadingdone` subscription or explicit DPR/zoom subscription in the inspected terminal helpers/viewport. The WebGL fallback correction samples `devicePixelRatio` only when its canvas ResizeObserver fires (`apps/web/src/components/terminalDevicePixelCorrection.ts:40–60`). **(guess)** A late selected-font load or DPR-only change at unchanged CSS dimensions could need explicit invalidation. This is an application-level gap to test; xterm/browser internals may cover part of it.
4. **(guess) Replayed TUI state or unsuccessful PTY resize can look like a paint problem and recover when a real size change makes the program redraw.** Reset handling applies ordered size state and replays the bounded snapshot (`apps/web/src/components/ThreadTerminalPanel.tsx:1493–1529`). Replay sends RIS and history; only exited sessions receive the mode-reset suffix (`apps/web/src/components/terminalReplyGuard.ts:43–53`). There is no observed corrupt snapshot or lost native resize in this investigation. This hypothesis rises only if buffer/PTY geometry evidence disagrees with the displayed surface; a repaint cannot reconstruct missing terminal output.

### Existing safeguards and limits of the trace

- (measured) Pane/document hiding tears down xterm, detaches replay, and disconnects the mount observer; showing it again recreates those resources (`apps/web/src/components/ThreadTerminalPanel.tsx:962`, `:1229`, `:1971–2056`, `:2357–2367`). Inactive non-host center surfaces are unmounted, rather than being kept as `display:none` terminals (`apps/web/src/components/CenterPanelSurfaceHosts.tsx:292–295`). (inferred) The zero-size concern is distinct from the explicit `shouldRender=false` path; there is no basis to claim every tab switch omits fitting.
- (measured) The terminal mount observer has no explicit zero-size check. The WebGL canvas correction skips nonpositive size but leaves its observer connected; it has no independent retry (`apps/web/src/components/terminalDevicePixelCorrection.ts:47–64`). (inferred) A later canvas-size notification can recover it; “ignored forever” is not established.
- (measured) Center dragging intentionally suppresses fitting/repainting while `data-resizing` is set. Release/cancellation flushes host rectangles, clears that flag, and dispatches `bibcode:center-panel-resize-end`, which the terminal listens to (`apps/web/src/components/CenterPanelWorkspace.tsx:419–433`; viewport `:2318–2355`). Pending frame/timer work is cancelled on cleanup and guarded against stale renderers. (inferred) Interrupted/suppressed trailing work merits coverage, but normal drag-end recovery already exists.
- (measured) Layout changes arriving during a pending ownership claim are reconsidered when that claim completes (`apps/web/src/components/ThreadTerminalPanel.tsx:1441–1471`). The client scheduler retains the latest pending resize and drains it (`packages/client-runtime/src/state/runtime.ts:228–269`); the PTY queue also coalesces to the final pending size (`apps/server/src/terminal/pty.rs:355–367`). (inferred) A generic “debounce drops the last resize” diagnosis contradicts these safeguards; failures and lifecycle cancellation need evidence.
- (measured) Theme changes update xterm options and refresh when the resolved theme changes, including an HTML class/style observer (`apps/web/src/components/ThreadTerminalPanel.tsx:634–643`, `:1951–1962`, `:2058–2062`). (inferred) Theme repainting is already implemented; no theme-specific reproduction was reported.
- (inferred) **Renderer independence:** the report with WebGL disabled makes WebGL context loss or texture-atlas corruption less likely as the sole cause. (measured) WebGL has its own lazy attachment, context-loss disposal, generation guards, and device-pixel backing-store correction (`apps/web/src/components/ThreadTerminalPanel.tsx:2093–2189`). (inferred) Any common lifecycle recovery fix must also preserve that WebGL handling and verify repaint after fallback; a WebGL-only fix would not account for the full report.

## Proposed fix behavior and decisions

- (inferred; agent's call) Reuse the shared terminal lifecycle to reconcile measurable geometry and repaint after layout, visibility, renderer creation/reattachment, font availability, and DPR changes. Coalesce events, but retain the final pending recovery. Prefer this over new per-panel workarounds because both hosts use the same viewport. Exact event wiring and whether an existing scheduling helper suffices are the implementer's call after reproducing a failing scenario.
- (inferred; agent's call) Treat local repaint and PTY size ownership as separate responsibilities. An owner fits its available area; a mirror repaints at the authoritative size and retains the existing “Sized for another window” behavior. Deduplicate unchanged PTY dimensions, never deduplicate a needed repaint solely because columns/rows match.
- (inferred; agent's call) Defer work for genuinely unmeasurable containers and guarantee recovery on the next valid layout/activation/renderer-ready event; avoid polling or a renderer restart as the default fix. Reuse existing generation/cancellation protection and preserve scrollback, selection where supported, input ordering, and live TUI modes.
- (inferred; agent's call) **size:M**: the expected fix is in shared frontend lifecycle/sizing with both host callers and lifecycle/visual regression coverage. It exceeds a one-line change but does not currently justify a protocol redesign. If evidence identifies native PTY failure or transcript corruption, reassess scope before implementing that separate cause.

## Acceptance scenarios / requirements

### R1. Settle geometry and paint [Must]

(inferred; source: reporter workaround and shared resize trace) WHEN a rendered terminal's layout, visibility, font availability, theme, or display scale changes, the terminal SHALL show its current output at the dimensions permitted by existing size ownership after that transition settles, without requiring a subsequent manual resize.

- (inferred) **Given** an owner terminal with a known grid/TUI fixture and WebGL on or off, **When** the right panel or Activity panel opens/closes, center splits change, or a tab/document becomes visible, **Then** row/column boundaries, cursor placement, and the fixture's current frame match the settled area without clipped/stale residual rows or an extra drag.
- (inferred) **Given** a terminal whose CSS dimensions remain constant, **When** its selected font becomes available, theme changes, or zoom/DPR changes, **Then** the rendered fixture has the current glyph metrics/colors and aligned drawing surface; unchanged columns/rows do not prevent a repaint.
- (inferred) **Given** a mirror owned by another window, **When** its local layout changes, **Then** it repaints at the owner's dimensions and does not steal ownership or alter the PTY size merely to repair paint.

### R2. Recover from unmeasurable or delayed creation [Must]

(inferred; source: hypotheses 1–2) IF a terminal is hidden, has a nonpositive measurement, or has not created its renderer yet, THEN the terminal SHALL defer geometry-dependent recovery until it has a measurable active renderer and complete that recovery without a further user resize.

- (inferred) **Given** an AI terminal waiting for host config with an early observer callback, **When** config arrives and a delayed font finishes loading without a container-size change, **Then** the first displayed fixture is correctly measured and painted.
- (inferred) **Given** a zero-size/hidden host, **When** it returns to positive size, including the same dimensions as before hiding, **Then** the fixture renders correctly; hidden/invalid geometry does not send a fabricated minimum or invalid size to the PTY.
- (inferred) **Given** a disposed renderer with pending font/frame/timer callbacks, **When** those callbacks settle, **Then** they neither repaint the old renderer nor resize a replacement session.

### R3. Preserve the final resize and session state [Must]

(inferred; source: existing resize/replay safeguards) WHEN a resize burst or reattachment finishes, the terminal SHALL converge to the latest valid dimensions permitted by size ownership while retaining the session's input/output order and live terminal modes.

- (inferred) **Given** a slow size claim or resize RPC and changing layout, **When** the final drag ends or is cancelled, **Then** the last valid settled dimensions reach the fixture PTY and its rendered view, with no repeated idle resize requests.
- (inferred) **Given** a known resize failure followed by a valid recovery event, **When** recovery runs, **Then** the final size can be retried; an older completion does not override newer geometry.
- (inferred) **Given** a live session reattaching with interleaved output/size events, **When** replay completes, **Then** its fixture frame and subsequent output remain ordered, with no replay bytes injected as input and no exited-session mode reset applied to a live TUI.

### R4. Capture the next failure safely [Should]

(inferred; agent's call, source: unknown visual symptom) WHEN development rendering diagnostics are explicitly enabled, the terminal SHALL expose bounded content-free evidence that distinguishes geometry, repaint, and PTY-size failures.

- (inferred) **Given** an isolated synthetic session, **When** the failure occurs and the panel is then resized, **Then** a before/after record correlates the last layout reason, renderer generation, container rect, proposed/applied columns/rows, ownership status, font readiness, DPR, renderer kind, size-request outcome, and repaint scheduling/completion.
- (inferred) **Given** diagnostics disabled or a real session containing private output, **When** normal terminal activity occurs, **Then** no terminal bytes, prompts, paths, credentials, or session-identifying values are captured by this diagnostic facility.
